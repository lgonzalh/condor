# T-012 - Instalador y puesta en marcha simplificada

Version: 1.1.0
Estado: Cerrada y congelada (completada, verificada, integrada y publicada)
Prioridad: Media

## Objetivo

Implementar una capacidad de puesta en marcha reproducible de Condor mediante
CLI y documentacion. La puesta en marcha simplifica verificar que el entorno
esta listo, identificar dependencias faltantes, preservar el estado local y
confirmar que Condor puede operar, sin descargar software ni modificar el
sistema.

## Alcance

T-012 debe:

- Implementar `condor preparar` y `condor preparar --json`.
- Verificar las condiciones necesarias para ejecutar Condor.
- Distinguir dependencias obligatorias de opcionales.
- Consumir/reutilizar las capacidades existentes de Assessment (sin reimplementar
  deteccion de OS/CPU/RAM/GPU/Git/Ollama/herramientas/modelos).
- Informar el estado del entorno e identificar dependencias faltantes.
- Proporcionar instrucciones manuales seguras cuando corresponda.
- Verificar que el estado local existe y es utilizable, preservando su contenido.
- Confirmar que Condor puede iniciar/operar correctamente.
- Producir salida textual y `--json`.
- Crear `INSTALACION_PUESTA_EN_MARCHA.md` documentando el proceso.

## No alcance

T-012 NO debe:

- crear MSI, EXE instalador, instalador grafico ni scripts de instalacion del
  sistema;
- descargar .NET, Ollama ni modelos; instalar modelos;
- configurar servicios del sistema, modificar variables del sistema ni realizar
  acciones administrativas;
- borrar, reinicializar ni sobrescribir el estado local
  (`%LOCALAPPDATA%\Condor\state\`) salvo lo que el contrato determine;
- gestionar modelos ni modificar Assessment;
- modificar T-001 a T-011;
- crear un segundo sistema de deteccion.

Las dependencias externas permanecen bajo control del usuario.

## Assessment

T-012 reutiliza el Assessment persistido (`AssessmentResult` via
`IStateStore.LoadAssessmentAsync`). Si se necesita informacion actualizada,
refresca el Assessment reutilizando `AssessmentService`/`IAssessmentService`.
No crea deteccion paralela.

## Dependencias

Obligatorias:

- Condiciones necesarias para ejecutar Condor (por ejemplo, .NET runtime
  requerido por la version distribuida).

Opcionales:

- Ollama, modelos, GPU, Git y herramientas de desarrollo.

T-012 no presenta una dependencia opcional como requisito absoluto si las
fuentes no lo establecen.

## Estado local

Nunca borra ni reinicializa `%LOCALAPPDATA%\Condor\state\`. El diagnostico es no
destructivo y solo verifica existencia y utilidad de los artefactos derivados
(assessment, context, plan, build, verification, cycle, vision).

## Determinismo y degradaciones

- Diagnostico determinista para un mismo estado del entorno; no depende de LLM
  para decidir si una dependencia existe.
- Degradaciones a distinguir: entorno listo; dependencia obligatoria faltante;
  dependencia opcional faltante; estado local ausente; estado local degradado;
  Assessment no disponible; capacidad opcional no disponible.
- Cada degradacion con motivo claro e instruccion segura cuando corresponda.

## Salidas

- `SetupResult` con: estado (`DetectionStatus`), motivo, dependencias
  obligatorias/opcionales con estado presente/ausente, estado del directorio
  local, resumen de disponibilidad y metadata.
- Seccion `PREPARAR` en texto y campo `preparacion` en `condor preparar --json`.

## Responsabilidades

| Capa | Responsabilidad |
|---|---|
| Condor.Core | Modelos de puesta en marcha (`SetupResult`, `SetupDependency`, `SetupLimits`), logica pura de evaluacion (`SetupEvaluator`): sin IO, determinista. |
| Condor.Infrastructure | `SetupService` (orquestacion: lee Assessment, diagnostica dependencias, verifica estado local) y `StateDirectoryProbe` (IO de lectura no destructiva del estado). |
| Condor.Cli | `PrepareCommand`, `PrepareRenderer`; comando `condor preparar`. |

## Criterios de aceptacion

- `condor preparar` (texto y `--json`) en espanol sin tildes, funcional en
  Windows.
- Diferencia dependencias obligatorias/opcionales; reutiliza Assessment.
- No duplica deteccion; no descarga; no configura servicios; no es destructivo.
- Preserva `%LOCALAPPDATA%\Condor\state\`.
- Diagnostico determinista; degradaciones claras.
- `INSTALACION_PUESTA_EN_MARCHA.md` creada distinguiendo instalacion de Condor,
  preparacion del entorno, dependencias externas, modelos locales, configuracion
  inicial, verificacion y puesta en marcha.
- Pruebas unitarias, integracion y arquitectura; E2E real.
- `1 archivo = 1 commit`, publicado, HEAD == origin/main, working tree limpio.
- No modifica T-001 a T-011.
