# T-001 - Bootstrap del MVP y Assessment inicial

Version: 1.0.0
Prioridad: Critica
Estado: Pendiente

## Objetivo

Crear la primera base ejecutable de Condor 1.0 para Windows y construir el primer componente funcional: un Assessment local capaz de observar el entorno antes de seleccionar modelos o ejecutar tareas.

Esta tarea es el primer paso de software, no solamente una preparacion documental.

## Alcance

### Debe hacer

1. Inspeccionar el repositorio y determinar la tecnologia mas adecuada para el MVP, justificandola en un registro de decision antes de fijarla.
2. Crear una estructura minima ejecutable para Condor en Windows.
3. Implementar una CLI inicial.
4. Implementar el Assessment local.
5. Detectar, como minimo:
   - sistema operativo;
   - CPU;
   - RAM;
   - GPU cuando sea detectable;
   - espacio disponible;
   - Git;
   - Ollama;
   - herramientas de desarrollo relevantes;
   - modelos Ollama disponibles.
6. Generar un resultado estructurado del assessment.
7. Mostrar un resumen legible en terminal.
8. Mantener toda la operacion local.
9. Dejar preparada la integracion posterior con Ollama sin acoplarla prematuramente al Assessment.
10. Crear pruebas basicas para los componentes que correspondan.
11. Actualizar los artefactos de operacion y el inventario arquitectonico afectados.

## No debe hacer

- No implementar todavia el Builder completo.
- No implementar el Context Engine completo.
- No ejecutar cambios sobre proyectos externos.
- No descargar automaticamente modelos grandes sin una decision posterior.
- No asumir que un modelo concreto es adecuado antes de evaluar el entorno.
- No introducir servicios cloud obligatorios.
- No construir una interfaz grafica.
- No convertir esta tarea en un framework general innecesario.

## Criterios de aceptacion

T-001 se considera terminada cuando:

- `Condor` puede iniciarse desde Windows.
- La CLI presenta identidad y estado inicial coherentes con el mockup.
- El Assessment se ejecuta sin depender de internet.
- El sistema identifica las capacidades disponibles del entorno.
- Ollama es detectado cuando esta instalado.
- Los modelos locales disponibles son identificados.
- El resultado del Assessment puede ser consumido por el siguiente componente.
- Existe evidencia de pruebas.
- El proyecto puede ser ejecutado por otro agente siguiendo la documentacion.
- `RELEVO.md`, `ESTADO_DESARROLLO.md`, `BACKLOG.md` y `KANBAN.md` quedan actualizados.

## Resultado esperado

El primer resultado funcional debe permitir llegar aproximadamente a:

Usuario inicia Condor
→ Condor observa
→ Condor analiza entorno
→ Condor informa capacidades
→ Condor queda preparado para recomendar modelo

La recomendacion de modelo completa pertenece a T-003.

## Regla de adaptacion

Si la capacidad de una tecnica avanzada depende del hardware o del modelo disponible, el agente debe implementar primero la alternativa viable mas simple y dejar registrada la evolucion prevista.

## Salida del relevo

El agente debe terminar indicando:

- tecnologia elegida y razon;
- estructura creada;
- comandos para ejecutar;
- pruebas ejecutadas;
- limitaciones encontradas;
- decisiones tomadas;
- siguiente tarea exacta.
