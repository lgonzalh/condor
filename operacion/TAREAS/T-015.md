# T-015 - Automatizacion de puesta en marcha y modelo LLM local

Version: 1.0.0
Estado: En ejecucion (implementacion completada; pendiente de cierre formal)
Prioridad: Alta

## Objetivo

Permitir que Condor (dentro de v1.x) asegure de forma automatica el modelo LLM
local durante la puesta en marcha, alineado con la experiencia esperada de Condor
(obtener el modelo cuando sea tecnicamente posible; reutilizarlo si ya existe).

## Flujo implementado

```
Assessment
  -> evaluar hardware real
  -> seleccionar modelo compatible (catalogo + MemoryBudget)
  -> comprobar inventario Ollama
  -> si ya existe: reutilizar (NO descargar nuevamente)
  -> si no existe: obtener mediante Ollama (timeout, reintentos, verificacion)
  -> actualizar Assessment/estado
  -> continuar el flujo
```

La obtencion se realiza mediante Ollama, con limite de reintentos, timeout y
verificacion posterior contra `/api/tags`. No permite bucles infinitos y degrada
de forma segura si la obtencion no es posible.

## Implementacion

Core (puro):
- `Models/ModelSelection.cs` (`ModelCandidate`, `ModelSelectionResult`)
- `Models/ModelSetupLimits.cs`
- `Selection/ModelSelector.cs` (seleccion determinista por hardware/catalogo/MemoryBudget + fallback)
- `Catalog/ModelCatalog.cs` (catalogo minimo: qwen2.5-coder:7b, llama3.2:3b, qwen3:8b)
- `Contracts/IModelAutoSetupService.cs`

Infrastructure (IO/orquestacion):
- `Retry/RetryPolicy.cs` (reintentos controlados)
- `Llm/OllamaModelOperator.cs` (obtencion via Ollama + verificacion)
- `Setup/ModelAutoSetupService.cs` (orquestacion)

Cli (presentacion):
- `Commands/PrepareCommand.cs` (invoca la automatizacion del modelo)
- `Presentation/ModelSetupRenderer.cs`

## Evidencia

- Build Release: 0 errores, 0 advertencias.
- Pruebas unitarias (Core): 186/186 (incluye ModelSelector).
- Pruebas de arquitectura: 20/20 (incluye ModelSelection puro).
- Pruebas de integracion (Infra): 177/177 (incluye ModelAutoSetup y RetryPolicy).
- Prueba real desde 0 modelos: `condor preparar` selecciono `llama3.2:3b`, lo
  obtuvo via Ollama, verifico instalacion y permitio inferencia real.
- Prueba de reutilizacion: con el modelo instalado, `condor preparar` no vuelve a
  descargar.
- Degradaciones y reintentos cubiertos por pruebas controladas.

## Modelo seleccionado

- `llama3.2:3b` (el de menor tamano del catalogo que cabe en el hardware real;
  memoria libre ~4.6 GB).

## Observaciones

- En la primera ejecucion, `condor preparar` muestra "Modelos locales: ausente"
  en la seccion PREPARAR (calculada antes del pull) mientras la seccion MODELO
  refleja el modelo obtenido. Es una inconsistencia cosmética de orden; no afecta
  la funcionalidad.
