# T-010 - Capacidades avanzadas de desarrollo

Version: 1.1.0
Estado: Cerrada y congelada (completada, verificada, integrada y publicada)
Prioridad: Media

## Objetivo

Implementar el nucleo SD-01 del ROADMAP_EVOLUCION sobre los motores existentes,
orquestando de forma determinista el ciclo parcial:

```
intencion -> Planner -> WorkPlan -> Builder -> Verifier
```

T-010 no implementa nuevas capacidades de Planner, Builder ni Verifier: los
**orquesta** y permite iteraciones controladas (regeneracion) para la continuidad.
El loop es parcial porque Architect no esta implementado.

## Alcance

T-010 debe:

- Implementar una orquestacion determinista que encadene Planner -> Builder ->
  Verifier (`condor avanzar`).
- Permitir regeneracion controlada interna al ciclo: cuando la verificacion
  permita recuperacion, iniciar una nueva iteracion determinista, limitada y con
  motivo registrado.
- Incluir checkpoints como mecanismo de continuidad: ciclo, etapa, resultado de
  etapa, iteracion, estado de recuperacion y siguiente accion prevista. Artefacto
  derivado; no sustituye plan.json, build.json ni verification.json.
- Proveer un harness de orquestacion (control de etapas, iteraciones, limites y
  resultados) para evidencia reproducible y pruebas E2E. NO es un nuevo Verifier.
- Exponer un unico comando publico: `condor avanzar` y `condor avanzar --json`.
- Centralizar los limites del ciclo de forma determinista.

## No alcance

T-010 NO debe:

- implementar Architect, Guardian ni simularlos;
- incorporar responsabilidades de Architect;
- ejecutar compilacion, pruebas ni analisis arquitectonico del proyecto objetivo;
- implementar verificacion semantica ni de calidad (linea SD-02/DE-002);
- agregar nuevas capacidades de Context Engine ni de Documenter;
- crear comandos `condor ciclo` ni `condor regenerar` en esta version;
- modificar T-001 a T-009 ni sus modelos congelados (WorkPlan, BuildResult,
  VerificationResult se consumen de solo lectura);
- introducir comportamiento autonomo no definido por este contrato.

## Entradas

- Intencion/solicitud del usuario (texto, espanol sin tildes).
- Estado persistido de Planner (`plan.json`), Builder (`build.json`) y Verifier
  (`verification.json`) via `IStateStore`.
- `CycleLimits` (limites centralizados del ciclo).

## Salidas

- `CycleResult` con: motivo, intencion, objetivo (del plan), iteraciones, etapas
  ejecutadas, resultado de cada etapa, estado de recuperacion, resumen (build
  aplicadas/verificadas) y metadata.
- `CycleCheckpoint` (artefacto derivado de continuidad).
- Seccion `AVANCE` en texto y campo `avance` en `condor avanzar --json`.

## Responsabilidades

| Capa | Responsabilidad |
|---|---|
| Condor.Core | Modelos de ciclo (`CycleResult`, `CycleCheckpoint`, `CycleStage`, `CycleLimits`), logica pura de orquestacion (`CycleEngine`): estados/transiciones deterministas, sin IO. |
| Condor.Infrastructure | `CycleService` (orquestacion real encadenando PlanService, BuildService, VerificationService) y persistencia de `cycle.json`/checkpoint. |
| Condor.Cli | `AdvanceCommand`, `AdvanceRenderer`; comando `condor avanzar`. |

## Limites del loop (CycleLimits, propuestos, pendientes de diseno)

- `MaxIterations` (limite de iteraciones/regeneraciones).
- `MaxStages` (limite de etapas por iteracion).
- `CycleTimeoutMilliseconds`.
- Valores de referencia: propuestos en el diseno tecnico (DEC-038).

## Estados y transiciones (borrador)

Etapas: `Planificar` -> `Construir` -> `Verificar` -> (regenerar si recuperable) ->
`Completado` | `Detenido` | `Degradado`.

Transiciones:

- `Planificar` exitosa -> `Construir`.
- `Construir` -> `Verificar`.
- `Verificar` correcta -> `Completado`.
- `Verificar` recuperable y iteracion < MaxIterations -> `Regenerar` (volver a
  `Planificar` con motivo).
- Cualquier degradacion irreversible -> `Detenido` (con motivo).
- Degradacion parcial -> `Degradado` (solo se reporta, no se regenera infinitamente).

Protecciones: contra iteraciones infinitas (MaxIterations), regeneraciones
ilimitadas, estados inconsistentes, resultados faltantes, degradaciones y errores
parciales. Cada iteracion queda identificada y trazada.

## Criterios de aceptacion

- `condor avanzar` (texto y `--json`) funcional y en espanol sin tildes.
- Encadena deterministamente Planner -> Builder -> Verifier usando sus servicios
  sin modificarlos.
- Regeneracion controlada: solo cuando Verifier permita recuperacion, hasta
  MaxIterations, con motivo registrado y sin ciclo infinito.
- Limitado por CycleLimits; degradaciones correctas sin excepciones.
- Checkpoint persistido como artefacto derivado, sin sustituir plan/build/
  verification.json.
- No modifica motores congelados ni T-001 a T-009.
- Determinismo (salvo GeneratedAtUtc).
- Evidencia automatizada (unitarias, integracion, arquitectura) y E2E real.
- `1 archivo = 1 commit`, commits publicados, HEAD == origin/main, working tree
  limpio.
