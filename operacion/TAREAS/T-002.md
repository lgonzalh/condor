# T-002 - Integracion local con Ollama

Version: 1.2.0
Prioridad: Critica
Estado: En revision

## Objetivo

Integrar Condor con el servidor local de Ollama para ejecutar inferencia local, consumiendo la informacion generada por el Assessment (T-001) sin acoplar el Assessment Engine con el motor de lenguaje.

Esta tarea convierte a Condor en un sistema capaz de conversar con un modelo LLM local, manteniendo la operacion 100% local y sin dependencia de internet.

## Alcance

### Debe hacer

1. Crear un cliente LLM local agnostico en Condor.Core (contrato y modelos de dominio).
2. Implementar la comunicacion con Ollama en Condor.Infrastructure mediante `http://127.0.0.1:11434/api/chat` con `stream: false`.
3. Agregar el comando `condor ask "<mensaje>" [--model <modelo>]` en la CLI.
4. Permitir consumir el resultado del Assessment persistido por T-001 (lectura aditiva de `IStateStore`).
5. Seleccionar el modelo de forma provisional: `--model` explicito o, en su defecto, el primer modelo disponible del Assessment (T-003 sera responsable de la recomendacion inteligente).
6. Manejar con mensajes claros: Ollama ausente, servidor detenido, modelo inexistente y errores de comunicacion.
7. Mantener la comunicacion exclusivamente en loopback (127.0.0.1) sin dependencias externas nuevas.
8. Crear pruebas unitarias, de integracion y de arquitectura.
9. Ejecutar una prueba funcional real desde la CLI.
10. Crear/actualizar `operacion/TAREAS/T-002.md` y los artefactos operativos correspondientes.

## No debe hacer

- No implementar T-003 (Recomendador de modelos).
- No implementar seleccion inteligente de modelo.
- No implementar Builder.
- No implementar Context Engine.
- No implementar embeddings.
- No implementar streaming.
- No descargar modelos automaticamente.
- No modificar el esquema `AssessmentResult` 1.0.0.
- No introducir servicios cloud ni dependencias de internet.
- No modificar el contrato existente de escritura de `IStateStore`.

## Criterios de aceptacion

T-002 se considera terminada cuando:

- `condor ask "<mensaje>"` ejecuta una inferencia local real con un modelo disponible.
- `condor ask "<mensaje>" --model <modelo>` permite elegir el modelo explicitamente.
- El modelo se selecciona del Assessment cuando no se especifica `--model`.
- La ausencia de Ollama, servidor detenido, modelo inexistente y errores de comunicacion producen mensajes claros sin excepciones.
- La comunicacion con Ollama usa exclusivamente 127.0.0.1.
- No se introduce ninguna dependencia externa nueva.
- Existe evidencia de pruebas unitarias, de integracion y de arquitectura.
- Existe evidencia de una prueba funcional real desde la CLI.
- Los artefactos operativos y el inventario arquitectonico quedan actualizados.

## Resultado esperado

El resultado funcional debe permitir:

Usuario inicia Condor
→ Condor observa y analiza el entorno (T-001)
→ Usuario expresa una intencion: `condor ask "..."`
→ Condor selecciona modelo (explicito o del Assessment)
→ Condor ejecuta inferencia local mediante Ollama
→ Condor entrega la respuesta

## Regla de adaptacion

Si la inferencia local no es viable (servidor ausente, sin modelos, hardware insuficiente), Condor debe degradar con un mensaje claro que indique la accion necesaria, sin fallar con excepciones.

## Resultado de la ejecucion

Implementacion completada y corregida (C-1 de la revision). Pendiente de revision final y aprobacion del commit.

Entregado:

- `Src/Condor.Core/Contracts/ILlmClient.cs`: contrato agnostico `CompleteAsync(LlmRequest, CancellationToken)`.
- `Src/Condor.Core/Models/LlmRequest.cs` y `LlmResponse.cs`: modelo de dominio (Model, Prompt, Temperature=0.7, MaxTokens opcional; Success, Content, Model, Error).
- `Src/Condor.Core/Evaluation/LlmModelSelector.cs`: seleccion explicita > primer modelo del Assessment (null si no hay); manejo seguro de `Tools`, `Ollama` y `Models` ausentes/null (correccion C-1).
- `Src/Condor.Core/Contracts/IStateStore.cs`: `LoadAssessmentAsync` aditivo (no rompe `SaveAssessmentAsync`).
- `Src/Condor.Infrastructure/Llm/OllamaClient.cs`: POST `http://127.0.0.1:11434/api/chat`, `stream:false`, timeout 180 s. Degradaciones: 404 modelo inexistente, errores HTTP con estado, timeout, `HttpRequestException` y cancelacion con mensajes claros. Sin validaciones de entrada produce errores claros sin excepciones.
- `Src/Condor.Infrastructure/State/LocalStateStore.cs`: `LoadAssessmentAsync` lee `assessment.json` del estado local y devuelve null ante JSON corrupto (correccion C-1: `JsonException` capturada, sin excepciones no controladas).
- `Src/Condor.Cli/Commands/AskCommand.cs` y `Src/Condor.Cli/Program.cs`: comando `condor ask "<mensaje>" [--model <modelo>]`, ayuda actualizada, exit code 0 en exito y 1 en degradacion/uso incorrecto.

Pruebas:

- 50 pruebas superadas (9 arquitectura + 15 unit + 26 integracion); 22 nuevas para T-002.
- Unit: `LlmModelSelectorTests` (explicito, primer disponible, sin modelos, sin assessment, sin Tools/Ollama/Models).
- Integration: `OllamaClientTests` (sin modelo/sin mensaje, 404 real, simulaciones con FakeHttpMessageHandler: sin conexion, 500, 404, parseo, endpoint 127.0.0.1), `LocalStateStoreTests` (round-trip, ausencia de archivo, JSON corrupto, JSON parcial) y `AskCommandTests` (assessment invalido y parcial: exit 1 sin consultar al modelo, con `LocalStateStore` real y cliente simulado que falla si se usa).
- Architecture: `CoreAgnosticTests` (Core sin `System.Net.Http`, sin procesos ni llamadas al SO, excluyendo obj/bin).
- Nota: `Condor.Infrastructure.Tests` incorpora referencia a `Condor.Cli` (proyecto Exe) para cubrir el comportamiento de `AskCommand`.

Evidencia funcional real (CLI `condor.exe`):

1. `condor ask "Responde unicamente con la palabra listo"` → modelo implicito `qwen-tools:7b` (primer disponible del Assessment), respuesta "Listo", exit 0.
2. `condor ask "Responde unicamente con la palabra ok" --model qwen3:8b` → modelo explicito, respuesta "ok", exit 0.
3. `condor ask` (sin argumentos) → "Uso: condor ask \"<mensaje>\" [--model <modelo>]", exit 1.
4. `condor ask "hola" --model modelo-inexistente-xyz` → "El modelo 'modelo-inexistente-xyz' no existe en el servidor de Ollama...", exit 1.
5. Ollama detenido + `condor ask "hola"` → "No fue posible comunicarse con el servidor de Ollama en 127.0.0.1:11434...", exit 1.
6. Ollama reiniciado + `condor ask "..." --model qwen-tools:7b` → respuesta "Listo", exit 0 (recuperacion).
7. `condor --help` muestra los comandos ask.
8. `assessment.json` corrupto (respaldo previo y restauracion posterior verificada) + `condor ask "hola"` → "No hay un modelo disponible. Ejecuta 'condor assess'...", exit 1, sin excepciones (correccion C-1).

Limitaciones conocidas:

- La seleccion de modelo es provisional (primero del Assessment); la recomendacion inteligente es responsabilidad de T-003 (DEC-015).
- Sin streaming: las respuestas se entregan completas (DEC-016).
- La inferencia depende del rendimiento local; con modelos grandes en CPU puede tardar.
- Deuda futura (observaciones de la revision no implementadas): `--model` sin valor se incluye en el prompt (O-1), timeout/cancelacion sin prueba automatizada (O-2), cuerpo del request sin test (O-3), prueba real dependiente de Ollama activo (O-4), `OllamaClient` sin IDisposable (O-5), AskCommand sin pruebas de parsing (O-6).
