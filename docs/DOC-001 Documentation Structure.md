# 01 - Documentation Structure

> **Documento:** DOC-001  
> **Proyecto:** Cóndor  
> **Versión:** 1.0  
> **Estado:** Draft

---

## Propósito

Definir la organización, estructura y estándares de la documentación oficial del proyecto.

---

## Principios

- Cada documento tiene una única responsabilidad.
- La información existe en un único lugar.
- La documentación evoluciona junto con el proyecto.
- Todo documento debe aportar valor.
- El conocimiento debe localizarse fácilmente.

## Estándar Documental

Todos los documentos deberán:

- Utilizar Markdown como formato oficial.
- Mantener una estructura uniforme.
- Tener un único propósito.
- Ser independientes.
- Permanecer consistentes con el Project Charter.

---

## Convenciones

### Encabezado

Todos los documentos utilizarán el siguiente formato:

```text

Proyecto
Versión
Estado
```

### Títulos

Se utilizarán únicamente tres niveles:

```text
#
##
###
```

### Separadores

```text
---
```

### Código

Todo bloque de código deberá indicar el lenguaje correspondiente.

## Definición de Terminado

Un documento se considera terminado cuando:

- Cumple una única responsabilidad.
- Sigue el estándar documental.
- Es consistente con el Project Charter.
- Puede comprenderse en pocos minutos.
- Está listo para ser versionado en Git.
