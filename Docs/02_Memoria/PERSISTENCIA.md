# PERSISTENCIA

Version: 1.0.0 Estado: Activo Nivel: 02 - Memoria Clasificacion:
Arquitectura

------------------------------------------------------------------------

# Proposito

Definir las reglas mediante las cuales el conocimiento generado por
Condor pasa de ser temporal a convertirse en conocimiento permanente del
proyecto.

------------------------------------------------------------------------

# Principios

-   Solo el conocimiento documentado es permanente.
-   Toda decision relevante debe persistirse antes de continuar el
    desarrollo.
-   Git constituye el historial oficial del proyecto.
-   La persistencia debe minimizar el trabajo manual del usuario.

------------------------------------------------------------------------

# Flujo de persistencia

1.  Generacion de conocimiento.
2.  Validacion de la decision.
3.  Incorporacion al documento oficial correspondiente.
4.  Actualizacion del estado del proyecto cuando aplique.
5.  Registro en Git.

------------------------------------------------------------------------

# Criterios de persistencia

Debe persistirse:

-   decisiones arquitectonicas;
-   reglas operativas;
-   definiciones permanentes;
-   cambios de alcance;
-   estructura documental;
-   interfaces y contratos.

No debe persistirse:

-   conversaciones;
-   ideas descartadas;
-   pruebas temporales;
-   comentarios transitorios.

------------------------------------------------------------------------

# Integridad

-   Nunca duplicar conocimiento entre documentos.
-   Cada decision debe tener un unico documento propietario.
-   Las referencias deben apuntar siempre al documento oficial.
